# ProFlow RAG｜公共上下文入口

> 目的：让新的 Chat / Work / Agent 在不读取完整聊天历史的前提下，能够准确接管 ProFlow RAG，并从当前唯一 checkpoint 继续。
> 更新时间：2026-09-04。

## 1. 公共上下文不是什么

公共上下文不是第二套 Spec，也不是聊天记录归档。正式产品、架构、领域、契约与验收仍以 `docs/specs/` 为设计真源；当前 Git、数据库、模型服务和公网链路以真实机械 readback 为运行事实真源。

## 2. 四层结构

```text
01-长期规则     所有后续 Chat 都必须遵守的低频稳定规则
02-当前接力     唯一滚动当前事实：做到哪里、下一步、禁止重做什么
03-执行知识库   可复用的基础动作与阶段流程 Runbook
90-历史记录     已结束 Round、旧 handoff、事故/审计原始证据，默认不加载
```

## 3. 新 Chat 最小读取顺序

1. 本 `README.md`。
2. `01-长期规则/01-项目总控职责与阶段门禁.md`。
3. `01-长期规则/02-公共上下文治理规则.md`。
4. `01-长期规则/04-执行纪律与工具规则.md`。
5. `02-当前接力/CURRENT.md`。
6. 严格按 `CURRENT.REQUIRED_CONTEXT` 加载对应 Spec / Runbook / 实战档案。
7. 只有追根因或审计旧证据时才读 `90-历史记录`。

## 4. 固定原则

执行前先恢复上下文，执行中保存真实 evidence，阶段结束按治理规则写回。`CURRENT` 只保留当前事实，不无限追加过程；稳定经验进入 Runbook；设计变化回正式 Spec；面试与学习过程进入独立实战档案。
