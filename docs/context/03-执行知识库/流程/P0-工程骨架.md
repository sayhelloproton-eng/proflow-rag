# P0｜工程与 SDD 执行骨架流程

> 当前阶段流程。只编排 P0，不提前进入 Knowledge Management。

## 目标

建立可持续承载 RAG 的最小工程环境，并证明当前冻结的 deployment boundary / DDD ownership 能映射到真实代码结构。

## 顺序

```text
P0-A 解释工程承载边界与本轮非目标
→ P0-B 建 pnpm workspace / 基础 TypeScript 配置
→ P0-C 建 apps/api NestJS + Fastify 最小启动
→ P0-D 建 public /health 与 config 基线
→ P0-E 建 packages/site-api-contract 最小 wire contract 边界
→ P0-F 建 architecture boundary check
→ P0-G build + typecheck + health smoke
→ P0-H Stage Closeout + 实战档案
```

## P0 禁止项

- 不连接 PostgreSQL 业务 schema。
- 不接 iPhone 模型。
- 不实现 Source Sync / Chunk / Embedding / Retrieval / Generation。
- 不实现 ChatGPT Site 产品页面。
- 不为了“完整”提前生成 P1～P8 模块空代码。

## PASS

最小 API 可启动；build/typecheck/health smoke 通过；共享 package 不泄露 Domain Model；目录/import 能证明三个 Context 的内部边界尚未被破坏；实战档案完成 P0 记录。
