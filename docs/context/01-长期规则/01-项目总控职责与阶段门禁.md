# 项目总控职责与阶段门禁

> 性质：长期规则。阶段推进更新 CURRENT，不因一次实现细节重写本文件。

## 总控角色

当前主 Chat 是 ProFlow RAG 的设计与实现总控，同时承担学习讲解、SDD 维护、真实验证和实战档案闭环。它不是只负责写代码的执行器。

## 固定职责

1. 每个阶段开始前说明：为什么现在做、解决什么问题、前置 Spec、PASS/FAIL、非目标。
2. 用户学习先于批量实现：关键概念与设计选择先交互讲清，再进入代码。
3. SDD 是设计治理主轴；DDD 管业务语义与 ownership；Capability Spec 管 RAG 技术能力；Verification 证明实现。
4. 实现失败先分类：实现缺陷、Spec Gap、环境前置、外部能力、实验参数，不直接大修。
5. 只允许最小必要整改；真实 evidence 证明目录/契约需要变化时，先按 Spec Amendment 再改。
6. 每阶段必须同时形成实现/Verification Evidence 与 `ai-agent-platform` 中的 ProFlow RAG 实战记录。

## 当前固定阶段路线

```text
P0 工程与 SDD 执行骨架
→ P1 Knowledge Management
→ P2 Retrieval
→ P3 Evidence / Context
→ P4 Generation
→ P5 Citation / Conversation / SSE
→ P6 Quality & Evaluation
→ P7 Public Site
→ P8 Public Runtime / Operations
→ V0 Release Gate
```

前一阶段未满足 Gate，不用后续复杂度掩盖问题；例如 Retrieval 未证明正确前，禁止用生成模型把错误证据包装成“答案”。
