# Knowledge｜源码同步与语料策略

状态：FROZEN_V0_2026-09-03

## 1. 权威来源
V0 只索引 ProFlow 的公开 GitHub `main`。不索引本地工作区、worktree、PR/feature branch，也不在用户请求时临时 `git pull`。

## 2. 同步触发
Mac 上的项目任务按周期读取远程 `main` SHA，并与当前 Active Snapshot 的 `source_commit_sha` 比较。SHA 相同立即结束；SHA 不同才启动 full rebuild。具体周期不冻结，必须先测真实 rebuild 时间与手机资源占用。

## 3. 拉取规则
- 构建开始时先解析目标 `commit_sha`，后续始终 checkout/fetch 该 SHA，而不是“最新 main”。
- 构建过程中 main 再次变化不改变当前 run 的输入；下一轮再处理更新 commit。
- 同时只允许一个 full rebuild；重复触发应合并或拒绝，不并发重建。

## 4. V0 Corpus 白名单方向
允许进入：README、公开 docs/spec、真实源代码、测试代码、公开配置说明、与项目能力直接相关的脚本/元数据。

## 5. 默认排除
`.env*`、token/credential、node_modules、dist/build、coverage、cache、日志、临时下载、二进制产物、机器私有配置、无意义 lockfile 内容、generated 文件、测试运行产物与其他无法提升问答价值的文件。

## 6. 安全过滤
语料接纳必须先经过路径/类型策略，再经过敏感内容检查。即使仓库公开，也不应假设所有历史或新提交都适合被 RAG 主动总结；发现疑似 secret 时该文档不得入库并产生明确告警。

## 7. 语料变更
V0 使用 full rebuild，所以文件删除、改名和移动通过新 Snapshot 自然收敛，不做复杂增量 reconciliation。Active Snapshot 切换后，旧 Snapshot 只保留上一成功版本用于回滚，其余按保留策略清理。

## 8. 验收
同步任务可证明“当前索引来自哪个 SHA”；main 无变化时不产生 Embedding 成本；敏感/生成文件不会进入 `CorpusDocument`；连续提交只在实际同步时构建当时解析到的确定 SHA。
