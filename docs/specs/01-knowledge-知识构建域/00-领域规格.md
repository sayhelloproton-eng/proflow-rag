# Knowledge｜知识构建域规格

状态：FROZEN_V0_2026-09-03

## 1. 领域使命
Knowledge Domain 唯一负责把 ProFlow GitHub `main` 的一个确定 commit 转换为完整、可验证、可切换的 Knowledge Snapshot。它把“仓库里的文件”变成“Retrieval 可以稳定查询的知识事实”。

## 2. 输入与输出
输入是 `RepositorySnapshot(commit_sha, fetched_at, repo_url)`；输出是 `KnowledgeSnapshot`。只有通过构建验证并被激活的 Snapshot 才能对 Retrieval 可见。

## 3. 核心对象
- `RepositorySnapshot`：不可变 Git 输入版本。
- `CorpusDocument`：经过语料过滤后接纳的逻辑文件。
- `Chunk`：结构感知后的最小检索单元。
- `EmbeddingBinding`：Snapshot 对 Embedding 模型、维度和配置的绑定。
- `KnowledgeSnapshot`：一整套文档、Chunk、Embedding、lexical 数据和构建元数据。
- `IngestionRun`：一次完整构建尝试及其阶段状态。

## 4. 业务不变量
- 一个 Knowledge Snapshot 只能绑定一个明确的 ProFlow commit。
- Active Snapshot 内的 Chunk 只能来自同一个 Repository Snapshot。
- Chunk 必须可追溯到 `commit_sha + file_path + line range`。
- Query Embedding 必须使用 Active Snapshot 对应的 Embedding 配置，禁止不同向量空间互相比较。
- 候选 Snapshot 构建失败不得删除或污染 Active Snapshot。
- Knowledge Domain 不读取 Conversation、Visitor、Feedback 或 Prompt。

## 5. 主流程
`Resolve main SHA → Fetch exact commit → Corpus Filter → Parse → Structure-aware Chunk → Embed → Build lexical/vector retrieval data → Validate → Activate`。

## 6. 异常策略
远程拉取、文件解析、Embedding、数据库写入或验证失败时，本次 IngestionRun 标记失败并保留诊断；Active Snapshot 不变。单个文件解析失败是否允许跳过由 Corpus/Parser Spec 决定，但不能静默丢失：必须产生可审计失败记录。

## 7. 发布给其他领域的契约
Knowledge 只向 Retrieval 发布 `ActiveKnowledgeSnapshotDescriptor` 与只读检索数据。Retrieval 不得调用 Knowledge 内部的 activate/delete/build 操作。

## 8. 验收
同一 commit、同一构建配置重复构建时，核心文档集合和可追溯坐标应确定；构建失败不影响在线查询；删除/改名文件不会残留为新 Active Snapshot 的幽灵知识；所有 Active Chunk 均能形成有效 GitHub commit Source。
