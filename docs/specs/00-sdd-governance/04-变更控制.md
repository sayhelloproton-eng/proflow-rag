# Spec 变更控制

状态：FROZEN_V0_2026-09-03

## 1. 触发来源

Spec 可由产品需求变化、真实实现不可行、模型/设备能力证据、Eval 回归、事故或安全发现触发修订。

## 2. 正确顺序

```text
发现问题 → 收集证据 → 定位 owning Spec → 标记 AMENDED → 修改设计 → 交叉审计 → 重新冻结 → 修改实现 → 重新验证
```

## 3. 禁止 silent divergence

如果代码必须临时绕过 Spec 才能恢复服务，必须留下明确的异常记录并尽快修复 Spec/实现偏差；不能让临时方案逐渐变成新的隐式架构。

## 4. ADR 与 Spec

ADR 记录“为什么选”；Spec 记录“选定后必须怎么工作”。若裁决变化，先新增/替代 ADR，再修改受影响 Spec。

## 5. 兼容性优先级

公共 API、Source Citation、Snapshot 可追溯、历史 Trace 可复盘和匿名隐私边界属于高兼容性资产；内部类名和文件路径不属于稳定公共契约。
