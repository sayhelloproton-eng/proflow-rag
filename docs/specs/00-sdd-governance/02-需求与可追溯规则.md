# Requirement 与 Traceability 规则

状态：FROZEN_V0_2026-09-03

## 1. 为什么需要 Traceability

RAG 项目容易出现“功能很多，但不知道哪条需求由谁实现、如何验收”。因此每条关键需求必须能追到能力与验收证据。

## 2. ID 规则

- `PRD-xxx`：产品需求。
- `SYS-xxx`：系统级不变量/约束。
- `DOM-KM-xxx`：Knowledge Management 领域。
- `DOM-GA-xxx`：Grounded Answering 领域。
- `DOM-QE-xxx`：Quality & Evaluation 领域。
- `CAP-xxx`：Capability Requirement。
- `CTR-xxx`：稳定 Contract。
- `VER-xxx`：验证案例/门禁。
- `ADR-xxx`：架构裁决。

## 3. 最小链路

关键需求至少形成：`Requirement → Owning Spec → Implementation Symbol/Module → Verification Case → Evidence`。

## 4. 不追求伪精确

不要求每一行代码绑定 Requirement ID。重点跟踪影响产品行为、数据正确性、信任边界、RAG 质量和运行稳定性的需求。

## 5. 变更要求

实现期若发现 Requirement 无法合理映射到当前 Context/Capability，优先检查设计是否错误，而不是随意增加 `common`、跨域 service 或直接数据库访问。
