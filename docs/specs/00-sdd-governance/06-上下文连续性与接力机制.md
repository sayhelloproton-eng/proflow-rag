# SDD Governance｜上下文连续性与接力机制

状态：FROZEN_V0_2026-09-04

## 1. 目标

ProFlow RAG 是跨多 Chat、跨阶段实现的长期工程。上下文连续性属于项目治理能力：下一执行者必须能在不读取完整聊天历史的情况下恢复当前目标、设计真源、checkpoint、required context、禁止重做项和下一动作。

## 2. 结构

权威公共上下文位于 `docs/context/`，固定分为：长期规则、当前接力、执行知识库、历史记录。它不替代 `docs/specs/`。

## 3. CURRENT Contract

`docs/context/02-当前接力/CURRENT.md` 是唯一滚动当前事实入口，至少包含：`CURRENT_STAGE / FINAL_GOAL / CURRENT_AUTHORITY_SNAPSHOT / LAST_COMPLETED / CURRENT_BLOCKER / NEXT_ACTION / DO_NOT_REPEAT / REQUIRED_CONTEXT`。

## 4. Authority

设计期望由已冻结 Spec/ADR 定义；当前实现由 Git/source 定义；运行状态由数据库/模型/tunnel/site 的真实 readback 定义；学习与面试叙事由独立实战档案记录。历史 Chat 不拥有上述 Truth。

## 5. Writeback

每个有意义 Round 必须执行 Context Closeout：更新 CURRENT，提炼稳定 Runbook，检查 Spec Amendment，保存 Verification Evidence，并同步实战档案。公共上下文不得成为绕过 SDD 的替代设计入口。

## 6. Verification

只使用 `README + 最小长期规则 + CURRENT + REQUIRED_CONTEXT` 的“失忆接管检查”必须能够明确当前 Gate、下一动作、真源、禁止重做项和恢复/写回入口；否则上下文机制判定不完整。
