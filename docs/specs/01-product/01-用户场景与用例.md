# 用户场景与用例

状态：FROZEN_V0_2026-09-03

## 1. Public Visitor

- `UC-001`：第一次进入站点，快速理解 ProFlow 是什么。
- `UC-002`：询问一个组件/能力的架构职责。
- `UC-003`：询问某个 CLI 命令、配置、源码 symbol 或错误行为。
- `UC-004`：询问“有没有测试证明”，需要检索 test evidence。
- `UC-005`：连续追问“它为什么这样做”，需要有限多轮语义理解。
- `UC-006`：点击 Source 跳到具体 commit 的文件行范围。
- `UC-007`：对回答点 👍 / 👎，不填写调查表。

## 2. Maintainer

- `UC-101`：ProFlow `main` 更新后构建新的 Knowledge Snapshot。
- `UC-102`：重建失败时继续服务旧 Snapshot，并能看到失败原因。
- `UC-103`：通过 request_id 复盘一次差回答的召回、RRF、Rerank、Context、模型和 Source。
- `UC-104`：把典型失败转成 EvalCase，比较参数/模型更新前后的结果。

## 3. 未来但非 V0

- `UC-F01`：ChatGPT/Codex 通过 MCP 使用同一 RAG 能力参与 ProFlow 开发。
- `UC-F02`：支持多个仓库/分支/发布版本。

未来用例不得反向增加 V0 的公共复杂度。
