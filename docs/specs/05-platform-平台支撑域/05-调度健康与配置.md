# Platform｜调度、健康检查与配置 Spec

状态：FROZEN_V0_2026-09-03

## 1. 调度职责
Source Sync 是后台周期任务，具体 cadence 根据 full rebuild 耗时和手机资源竞争决定。调度器只负责“何时检查”，Knowledge Domain 决定是否需要构建和如何构建。

## 2. Rebuild 互斥
任何时刻只允许一个 Knowledge full rebuild。新调度命中已有 run 时应跳过/记录，不另起并发；在线请求优先于后台 Embedding。

## 3. Health 分层
Public `GET /health` 只返回最小 liveness/readiness。Protected internal health 可展开 API、DB、Active Snapshot、Tunnel、iPhone capabilities/queue 等依赖状态。

## 4. Readiness
没有 Active Snapshot 时，服务进程可能 alive 但 RAG chat 不 ready；模型临时不可用时 search 可能 ready、generation 不 ready。健康状态需要区分组件能力，而不是一个布尔值掩盖问题。

## 5. 配置
所有环境差异通过 typed config 管理：DB URL/parts、Dev Tunnel、API key、model base URL、timeouts、rate limits、sync cadence 等。`.env.example` 只放字段名和安全示例，不放真实 LAN secret。

## 6. 可调参数来源
研发初期参数可来自 config；经过 Eval 后把基线值记录到版本化配置/文档。架构 Spec 不写死未测的 8k/16k、15 分钟、Top 20 等数值。

## 7. 时间与时区
数据库记录统一使用带时区 timestamp/UTC；Site 展示可本地化。调度以 Mac 的明确时区/系统 scheduler 语义执行，避免 DST/时区漂移导致重复任务。

## 8. 验收
health 能区分 alive/ready/degraded；同一时刻不会启动两个 rebuild；配置缺失在启动时 fail fast；公开 health 不泄露拓扑；运行参数变化可在 trace/run 中追溯。
