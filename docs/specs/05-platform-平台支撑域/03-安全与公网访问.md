# Platform｜安全与公网访问 Spec

状态：FROZEN_V0_2026-09-03

## 1. 公网调用链
Browser → ChatGPT Site → Site Server → HTTPS Dev Tunnel → NestJS。浏览器不直接持有 Backend service secret。

## 2. 服务鉴权
Site Server 在 Secrets 中保存 `PROFLOW_RAG_API_KEY`，Backend `.env` 保存对应值。调用使用 `Authorization: Bearer ...`。Secret 不写入 Git、不返回浏览器、不出现在 Trace/日志。

## 3. Public / Internal API
公开 Site 只调用必要 chat/source 等 API。`/internal/*` 的 rebuild、详细 health、管理能力需要独立保护；不能因为知道 Dev Tunnel URL 就可触发全量 Embedding 或查看内部网络信息。

## 4. Abuse Protection
匿名站点必须有限流、请求体大小、conversation 长度、输出 token、queue 长度和模型 timeout 保护。V0 可使用 visitor/IP 组合做 rate limiting，但 raw IP 不作为长期身份。

## 5. Corpus Safety
Ingestion 在写 RAG 前过滤 secret/env/credential/私有机器工件。Source API 只能返回 approved corpus 中的 GitHub 证据，不能借 path 参数读取任意本机文件。

## 6. CORS 与 CSRF
Site 主要由服务端调用 Backend，CORS 只作为浏览器策略补充，不等于鉴权。若将来增加浏览器直连的无 secret API，需要单独评估 Origin/CSRF，不在 V0 通过“允许所有 CORS”省事。

## 7. 日志
禁止记录 Bearer token、完整模型认证信息、数据库密码。错误日志默认最小化用户网络信息；公开 health 只返回最少 readiness，不暴露 LAN IP、数据库名称细节或 Tunnel 管理信息。

## 8. 验收
无 secret 的直接 Dev Tunnel 请求被拒绝；浏览器源码中找不到 API key；数据库和 iPhone 端口从公网不可达；internal endpoint 与 public key 权限边界有效；异常日志不泄密。
