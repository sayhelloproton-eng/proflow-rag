# ProFlow RAG｜系统上下文

状态：FROZEN_V0_2026-09-03

## 1. 系统边界
系统由公网 Site、本地 Mac RAG 服务、本地 PostgreSQL、内网 iPhone 模型服务和 GitHub ProFlow 仓库组成。Site 是公开交互入口；Mac 是 RAG 的控制平面与数据平面；iPhone 只提供推理算力；GitHub `main` 提供可复现知识源。

```text
Internet User
    ↓
ChatGPT Sites
    ↓ Site Server / HTTPS / Bearer Secret
Microsoft Dev Tunnel
    ↓
Mac: NestJS RAG API
    ├─ PostgreSQL + pgvector
    ├─ Knowledge / Retrieval / Conversation / Evaluation
    └─ Model Gateway ──LAN──> iPhone Model Service

GitHub: ProFlow main
    ↓ periodic source sync
Mac: Knowledge Build → Snapshot → Activate
```

## 2. 安全边界
- 浏览器不得持有 RAG Backend 的服务密钥。
- Site Server 才能使用 `PROFLOW_RAG_API_KEY` 调用 Dev Tunnel 后端。
- PostgreSQL 不开放公网端口。
- iPhone 模型服务只在 LAN 内可达，不暴露公网。
- Dev Tunnel 只映射 ProFlow RAG HTTP 服务，不映射数据库或手机模型端口。
- `/internal/*` 管理能力与公开 Chat API 分离，并采用更严格保护。

## 3. 在线请求路径
一次用户问题进入 Site 后，由 Site Server 转发到 RAG API；Conversation 负责多轮语义与路由，Retrieval 基于当前 Active Knowledge Snapshot 得到 EvidenceSet，Context Builder 选择证据，Model Gateway 调用手机 FAST/THINK 模型并把生成流向上游。最终事件带回 Sources、request_id 和完成状态。

## 4. 离线知识构建路径
Mac 定期检查 ProFlow `main` 的远程 SHA。只有 SHA 变化时才创建新的候选 Snapshot，执行拉取、过滤、解析、结构化 Chunk、Embedding、索引、验证。候选 Snapshot 完整通过后才原子切换为 Active；任何失败都不能破坏当前在线 Snapshot。

## 5. 关键资源约束
iPhone 被视为单个受限推理设备。在线 Query Embedding、Reranker、FAST/THINK Generation 与离线批量 Embedding 会竞争同一设备资源，因此 Model Gateway 必须统一调度，在线交互优先于离线 rebuild，初始并发按 1 处理，后续只允许通过真实压测放宽。

## 6. 可迁移性
V0 选择本地 Mac + Dev Tunnel 是成本与学习目标驱动，不允许把领域逻辑写死在本机路径、某个 LAN IP 或 launchd 中。未来迁移到云主机、其他数据库或其他模型 Provider 时，领域协议与公共 API 应保持稳定。
