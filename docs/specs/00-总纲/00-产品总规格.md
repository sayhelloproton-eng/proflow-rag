# ProFlow RAG｜产品总规格

状态：FROZEN_V0_2026-09-03

## 1. 产品目标
ProFlow RAG 是一个公开的真实工程项目，而不是一次性 RAG Demo。它首先让外部用户通过 ChatGPT Sites 理解 ProFlow 是什么、有哪些能力、架构如何工作，并能够基于 ProFlow 公开源码、文档与测试向 RAG 提问；后续同一套知识能力还可以为 ProFlow 自身持续迭代提供上下文增强。

## 2. V0 必须完成的用户价值
- 用户打开站点后能够快速知道 ProFlow 的定位、核心能力与主要架构。
- 用户可以自然语言询问 ProFlow 的概念、源码、测试和当前开发阶段事实。
- 回答必须由检索证据支撑，并展示可点击的 GitHub Source。
- Chat 必须流式返回，不能等完整生成后一次性展示。
- 默认走 FAST；只有明确命中复杂任务才进入 THINK。
- 用户无需注册登录即可体验，并可用极简 👍 / 👎 反馈回答质量。
- 所有真实问答形成可审计 RAG Trace，用于后续质量改进。

## 3. V0 非目标
- 不建设通用知识库 SaaS，不支持任意用户上传资料。
- 不建设用户账号、付费、团队 Workspace 或权限产品。
- 不做多仓库、多分支、多版本切换；知识源只认 ProFlow GitHub `main`。
- 不把 OpenAI Responses API 作为必要链路，不依赖收费云模型完成核心能力。
- 不把 OpenAI Secure MCP Tunnel 作为公网 Site 的主入口；Chat/Codex MCP 接入延后。
- 不采用微服务、Docker、ORM、独立向量数据库或 Elasticsearch 作为 V0 前提。

## 4. 权威事实源
公开 RAG 的源码权威来源是 ProFlow GitHub 仓库的 `main` 分支。每次知识构建必须解析出明确 `commit_sha`，所有可引用证据绑定该不可变 commit，而不是绑定会移动的 `main` URL。V0 只有一套 Corpus / Active Snapshot，不人为拆分 Public/Dev 两套知识库；开发阶段内容只要已经进入公开 `main`、通过语料安全过滤且对理解项目有价值，就可以成为展示事实。

## 5. 运行基线
- 公网展示与 ChatWeb：ChatGPT Sites。
- 公网入口：Microsoft Dev Tunnel，仅暴露 Mac 上的 RAG HTTP 服务。
- 后端：TypeScript + NestJS，底层 HTTP 使用 Fastify。
- 数据库：Mac 本机原生 PostgreSQL，启用 pgvector；NestJS 通过 `pg` 直接 SQL 访问。
- 模型算力：内网 iPhone 服务；当前生成基线为 Qwen 3.6 4B，Embedding 与 Reranker 也优先由手机提供独立模型能力。

## 6. 开发方法
项目采用 SDD。Spec 是实现前的权威设计源；当前暂不采用 TDD 驱动，但必须保留必要的集成验证、Smoke Test 和 RAG Eval。RAG 的主要质量门不是单测覆盖率，而是检索、重排、Grounding、引用、路由和延迟是否达到验收标准。

## 7. 成功标准
V0 成功不是“接口能返回答案”，而是：公开站点可访问；ProFlow 关键问题能稳定命中正确证据；回答不脱离证据；来源可追溯；手机模型在受控并发下流式响应；失败时能够明确降级或拒答；RAG Trace 足以定位检索、重排、Context 或生成中的具体问题。
