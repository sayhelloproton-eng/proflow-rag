# ProFlow RAG｜V0 架构裁决

状态：FROZEN_V0_2026-09-03

本文只记录已经讨论并接受的架构决策。具体可调参数由领域 Spec 与 Eval 决定。

## 产品与仓库
- `proflow-rag` 为独立公开 GitHub 仓库，与 ProFlow 主仓分离。
- 前端 Site 源码、后端、数据库 schema、RAG 核心、Eval 与运维脚本在同一仓库维护。
- ProFlow 知识源只认远程 GitHub `main`，不直接索引本地 ProFlow 工作区和 feature branch。
- V0 只有一套 Corpus / Active Snapshot，不建设 Public/Dev 双索引；真正需要过滤的是敏感、无价值和生成类内容。
- `proflow-rag` 自身普通代码提交默认只影响应用代码/站点/CI，不自动触发 ProFlow 知识重建；只有 ProFlow `main` SHA 变化，或 parser/chunker/embedding/corpus policy 等索引配置显式变化时才需要 rebuild。

## 后端与数据
- 后端采用 NestJS + Fastify + TypeScript，形态为模块化单体，不拆微服务。
- PostgreSQL 在 Mac 原生部署，不使用 Docker Compose 作为本机主运行方式。
- pgvector 是 PostgreSQL 扩展，用于向量类型与相似度检索；它不是独立数据库。
- NestJS 使用 `pg` 直接连接 PostgreSQL并执行 SQL，不引入 ORM。
- 数据库名使用 `proflow_rag`，并使用 `rag`、`ingestion`、`app`、`system` schema 做命名空间隔离。

## RAG Pipeline
- 文档、源码、测试都进入语料，但使用不同结构化 Chunk 策略；固定长度 Chunk 仅作为 Eval baseline。
- Retrieval 从 V0 就采用 Hybrid Search：PostgreSQL-native lexical + pgvector semantic。
- 两路召回先用 RRF 融合，再进入独立 Reranker；Reranker 是 V0 必经学习环节，失败时允许退化到 RRF 排序。
- 每次回答必须基于 Evidence，并展示绑定 `commit SHA + path + line range` 的 GitHub Source。
- 作为学习项目，RAG 核心链路（parse/chunk/embed/retrieve/fuse/rerank/context/generate/eval）必须在项目内显式可见、可审计；不得用 LangChain/LlamaIndex 等高层框架把关键阶段黑盒化。允许使用解析器、tokenizer、数据库驱动和模型客户端等基础库。

## 模型
- 模型算力优先全部来自内网 iPhone 服务，不使用收费云 API 作为 V0 必需项。
- 当前生成基线是 Qwen 3.6 4B；FAST 默认，THINK 仅由确定性复杂度规则命中。
- Embedding 与 Reranker 使用独立模型能力，候选模型在真实 endpoint/质量/延迟验证后冻结。
- Model Gateway 统一封装模型调用和设备调度；初始设备推理并发为 1。

## 公网与生命周期
- ChatGPT Sites 作为公开展示与 ChatWeb。
- Microsoft Dev Tunnel 作为 Site 到 Mac RAG API 的公网 HTTPS 入口。
- Site Server 用 Bearer API Key 调 Backend；密钥不能进入浏览器。
- 开发期直接使用项目 `pnpm dev` 和项目脚本；稳定后才允许 launchd 调用仓库自身 start script。
- ProFlow RAG、Dev Tunnel、PostgreSQL 使用独立命名和生命周期，不修改既有 gptweb-mcp 管理方式。

## 数据更新
- 开发期以定时检查 `main` 为主，不对每个 commit 立即重建；具体频率由真实 full rebuild 时间决定。
- V0 使用全量 Snapshot rebuild，新 Snapshot 验证成功后原子激活；保留上一个成功 Snapshot 用于快速回滚。

## 交互与审计
- Chat 必须 SSE 流式返回，并尽可能降低 TTFT（首 Token 时间）。
- 匿名可用、不建设登录；保存 visitor/conversation/request 区分的聊天与 RAG Trace。
- Visitor 使用随机 ID，不做侵入式 Canvas/WebGL 浏览器指纹。
- 用户反馈只有 👍 / 👎，无文字问卷。
