# ProFlow RAG｜统一语言（Ubiquitous Language）

状态：FROZEN_V0_2026-09-03

为了避免文档、代码和数据库对同一概念使用不同名字，以下术语作为 V0 统一语言。

- **Repository Snapshot**：从 ProFlow GitHub `main` 解析出的某个确定 `commit_sha` 的源码快照。它是输入事实，不等于 RAG 索引。
- **Corpus（语料）**：经过安全与价值过滤后，允许进入 RAG 的文档、源码和测试集合。
- **Corpus Document**：语料中的一个逻辑源文件记录，保留 path、类型、commit 与内容哈希。
- **Chunk（知识块）**：由 Parser/Chunker 从 Corpus Document 产生的可检索基本单元，必须能回到原始文件与行范围。
- **Knowledge Snapshot（知识快照）**：一个完整可检索版本，包含特定 Repository Snapshot 经特定 Parser、Chunker、Embedding 配置构建出的索引事实。
- **Active Snapshot**：当前线上查询唯一允许读取的 Knowledge Snapshot。
- **Candidate（候选）**：Lexical/Vector 召回的待融合或待重排 Chunk。
- **Evidence（证据）**：经过融合与重排后，被认为足以参与回答的候选，带不可变 Source 坐标。
- **EvidenceSet（证据集）**：Retrieval Domain 对 Conversation Domain 的正式输出，不是裸 `Chunk[]`。
- **Standalone Query**：结合有限多轮上下文，将“它、这个模块”等指代改写成可独立检索的问题。
- **Context Plan**：Conversation 为本轮生成选定的 Evidence、历史上下文与 token 预算计划。
- **FAST / THINK**：同一生成能力的两种路由模式；FAST 是默认快速路径，THINK 仅用于命中复杂推理条件的请求。
- **Source Citation**：展示给用户的可验证来源，必须绑定 commit、文件路径和行范围。
- **RAG Trace**：从问题、检索、融合、重排、Context、模型路由到输出与耗时的完整审计轨迹。
- **Eval Case**：包含问题、期望证据/行为和验收条件的可重复质量样本。

禁止在正式 Spec 中用 `index` 同时指代数据库索引、知识快照和向量索引；必须写清具体含义。
