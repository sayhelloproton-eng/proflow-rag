# ProFlow RAG｜端到端验收场景

状态：FROZEN_V0_2026-09-03

本文件不是测试用例集合，而是跨 DDD 领域的 SDD 验收场景。实现阶段的 Smoke、Integration 与 RAG Eval 必须覆盖这些业务链路。

## 场景 A：简单项目事实走 FAST
用户问“ProFlow 是做什么的？”Site 建立匿名 turn；Conversation 保持 FAST；Retrieval Hybrid 找到 README/docs 等 Evidence；生成快速流式返回；最终 Sources 指向正确 commit/lines；Trace 记录 FAST 原因与 TTFT。

通过条件：不进入 THINK；Evidence 正确；答案不扩写索引外当前事实；Source 可点击；首 token 延迟达到 baseline 目标。

## 场景 B：复杂架构关系走 THINK
用户问需要跨 Runtime、Harness、Agent 等多证据综合的问题。Conversation 的确定性规则命中 THINK；Retrieval 提供多源 EvidenceSet；Context 保持证据优先；Think 生成仍必须 grounded。

通过条件：RoutingDecision 可解释；不是因为“问题长”就无脑 THINK；关键结论都能映射到 Evidence。

## 场景 C：精确工程标识符
用户输入 CLI、函数名、路径或 error string。Lexical 分支保留 exact signal，同时 Vector 参与语义补充，RRF+Reranker 形成最终证据。

通过条件：Query Rewrite 不丢精确词；expected symbol/path/test 被召回；中文上下文不会破坏 exact identifier。

## 场景 D：无证据问题
用户询问 ProFlow 仓库中不存在的能力或完全无关知识。Retrieval 返回 low-confidence/no-evidence，Conversation 不调用生成模型编造 ProFlow 事实，Site 显示明确“当前索引没有足够依据”。

通过条件：无虚假 Source；Trace 能解释为何 no-evidence。

## 场景 E：多轮指代
第一轮询问 Runtime，第二轮问“那它和 Harness 呢？”。Conversation 用有限近期上下文形成 Standalone Query，每轮重新 Retrieval，而不是只把旧答案当事实。

通过条件：指代正确；旧历史不挤掉本轮 Evidence；会话接近预算时有明确提醒。

## 场景 F：Reranker 故障
Hybrid + RRF 正常，但手机 Reranker timeout。Retrieval 标记 degraded 并回退 RRF 排序；如果 Evidence 仍达可信门槛则继续回答，否则 no-evidence。

通过条件：不因 Reranker 单点故障让整个 Site 必然挂死；Trace 明确 `rerank_degraded`。

## 场景 G：手机模型离线/拥塞
iPhone 不可达或队列达到保护阈值。Model Gateway 快速返回可识别状态，Site 告知模型暂不可用/繁忙，不无限 loading；公网流量不能绕过队列直接并发轰手机。

通过条件：Backend/DB 仍可健康诊断；无无限 retry；已发 token 的生成不自动 replay。

## 场景 H：Full Rebuild 不影响在线 Snapshot
ProFlow `main` SHA 变化，后台创建候选 Snapshot；此时公网 Chat 继续只读旧 Active。构建过程中注入失败，Active 不变；下一次成功 rebuild 后原子切换。

通过条件：不存在半成品检索窗口；在线 Trace 始终指向一个明确 snapshot/commit；previous snapshot 可回滚。

## 场景 I：Source 不随 main 漂移
RAG 基于 commit A 回答后，ProFlow main 已到 commit B。用户点击旧回答 Source 时仍打开 GitHub commit A 对应行，不跳到 main 的新内容。

通过条件：历史答案可复核，Source URL 使用 immutable commit。

## 场景 J：极简反馈形成回归资产
用户对回答点 👎。Feedback 与 request_id 幂等绑定；审计可直接查看该请求的候选、Rerank、Context、mode、timings 和答案，并可人工转为 Eval Case。

通过条件：无需用户登录；不保存侵入式浏览器指纹；旧 Snapshot 清理后仍可复盘该回答。
