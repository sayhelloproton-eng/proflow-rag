# Conversation｜会话问答域规格

状态：FROZEN_V0_2026-09-03

## 1. 领域使命
Conversation Domain 负责把匿名用户的一轮问题，结合必要的近期会话语义和 Retrieval 提供的 EvidenceSet，组织成一次可流式、可引用、可审计的回答。它拥有“怎么聊、什么时候 THINK、Context 怎么装、答案怎么流出来”的规则，但不拥有知识索引和数据库实现。

## 2. 核心对象
- `Conversation`：匿名会话线程。
- `Turn`：一次 user question + assistant answer 的业务单元。
- `StandaloneQuery`：消除多轮指代后的独立检索表达。
- `RoutingDecision`：FAST/THINK 的确定性路由结果与原因。
- `ContextPlan`：System、Question、Evidence、History 在 token budget 中的分配。
- `Answer`：流式正文、完成状态与 SourceCitations。

## 3. 业务不变量
- 每个新 Turn 都执行新 Retrieval，不能只依赖旧答案记忆。
- Evidence 优先级高于旧聊天历史，不能为了“记住对话”把有效证据挤出 Context。
- FAST 是默认路径；THINK 必须记录明确命中原因。
- 没有足够 Evidence 时不得把模型常识包装成 ProFlow 事实。
- Sources 的 commit/path/lines 事实来自 Evidence，不由生成模型自行编写。
- 生成流已向用户发送 token 后，不允许自动重试整个 Generation 造成重复或语义分叉。

## 4. 主流程
`User Turn → bounded history understanding → Standalone Query → Retrieval → Routing → Context Plan → Generation Stream → Source Finalization → Persist Trace/Turn`。

## 5. 失败与降级
Query rewrite 失败可退回原始问题并保留 exact terms；Reranker 失败由 Retrieval 降级；模型不可用时返回明确 `MODEL_UNAVAILABLE`；Context 超预算时优先丢旧 history，接近硬上限要求用户新建会话。

## 6. 与其他领域关系
Conversation 调用 Retrieval 获取 EvidenceSet，通过 Platform Model Gateway 调生成模型，把执行事实发送给 Evaluation。Delivery 只把 HTTP/Site 输入映射成 Conversation command 并展示其输出。

## 7. 验收
多轮指代可正确理解；简单事实不误进 THINK；复杂架构/多证据任务能够命中 THINK；TTFT 可测；no-evidence 不幻觉；答案 Sources 与 EvidenceSet 一致；超长会话有明确提示而不是无限积累。
