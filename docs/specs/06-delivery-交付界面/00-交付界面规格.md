# Delivery｜交付界面规格

状态：FROZEN_V0_2026-09-03

## 1. 定位
Delivery 不是核心 Domain，它负责把外部协议和 UI 映射到 Conversation/Application 能力。V0 有两个主要交付面：NestJS HTTP API 与 ChatGPT Sites。

## 2. 责任
- 校验/解析 HTTP 输入并生成 application command/query。
- 把 Conversation 的流式事件翻译成 SSE。
- 把 SourceCitation、错误码、request_id 转成稳定公共响应。
- 在 Site 中呈现 ProFlow 项目介绍、Ask ProFlow、Sources 与极简反馈。

## 3. 不负责
- 不直接执行 SQL 检索。
- 不直接调用 iPhone 模型。
- 不拥有 FAST/THINK 规则、Evidence selection 或 Snapshot lifecycle。
- 不让 UI 临时需求反向修改核心领域数据模型。

## 4. 公共契约稳定性
Delivery 可以换实现，例如未来增加 MCP/CLI，但核心领域的 StandaloneQuery、EvidenceSet、Answer 等语义不因 UI 变化而变化。公共 HTTP schema 改动属于需先更新 Spec 的设计变化。

## 5. 前后端同仓
Site source/config 与 Backend 在同一个 `proflow-rag` 仓库中维护，支持一次 commit 闭环修改 API 与 UI。ChatGPT Sites 是发布/运行环境，不是唯一源码来源。

## 6. 验收
前端不包含 Backend secret；Site 不越过 API 直接碰数据库/模型；错误能稳定映射为用户可理解状态；替换展示层不会要求重写 RAG 核心流程。
