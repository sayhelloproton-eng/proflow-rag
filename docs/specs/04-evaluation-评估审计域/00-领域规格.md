# Evaluation｜评估审计域规格

状态：FROZEN_V0_2026-09-03

## 1. 领域使命
Evaluation Domain 负责把“RAG 好不好”从感觉变成可复盘事实。它记录真实 RAG Trace、用户极简反馈、人工/自动基准样本与回归结果，用于判断问题发生在 Retrieval、Rerank、Context、Routing、Generation 还是 Source Grounding。

## 2. 核心对象
- `RAGTrace`：一次 request 的完整执行事实。
- `Feedback`：与 request_id 绑定的 👍 / 👎。
- `EvalCase`：稳定、可重复的问题与期望证据/行为。
- `EvalRun`：某 Snapshot/模型/参数组合上的批量评估。
- `MetricResult`：检索、排序、Grounding、路由和性能指标。

## 3. 不变量
- Trace 必须能定位到 request、conversation、snapshot、model/config version。
- 旧 Knowledge Snapshot 被清理后，历史 Trace 仍能复盘当时实际 Evidence 与生成 Context。
- 用户反馈不是 Ground Truth，只是发现问题的信号。
- Evaluation 写入失败不能让已完成的在线回答被伪造成业务失败；但必须产生运维告警。
- 不保存模型私有推理链；只保存必要输入、证据、路由、输出和运行指标。

## 4. 评估层次
先评 Retrieval 是否找对，再评 Rerank 是否排对，再评 Context 是否选对，再评 Answer 是否 grounded，最后评 Routing/Latency。不能只看最终回答“像不像对的”。

## 5. 数据来源
人工整理的 ProFlow benchmark 是稳定基线；真实站点中的 👎、no-evidence 误判、慢请求与典型成功请求可以匿名化后沉淀为回归案例。

## 6. 验收
任何一次差回答都能从 request_id 追到候选、RRF、Reranker、最终 Context、生成模式和 Source；版本/参数变化后能在同一 EvalCase 集上做 before/after 比较。
