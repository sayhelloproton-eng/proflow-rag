# Retrieval｜检索域规格

状态：FROZEN_V0_2026-09-03

## 1. 领域使命
Retrieval Domain 负责把一个可独立检索的问题转换成 EvidenceSet。它必须兼顾自然语言语义、工程精确词、源码 symbol/path、CLI/error name 与测试证据，不能把“向量相似”误当成“事实正确”。

## 2. 输入与输出
输入：`RetrievalQuery(query_text, snapshot_id, optional filters/context hints)`。
输出：`EvidenceSet(query, evidences, confidence, retrieval_trace)`。

## 3. 领域对象
- `Candidate`：某一路召回得到的 Chunk 与该路 rank/score。
- `FusionResult`：多路候选去重与 RRF 后的统一排序。
- `RerankResult`：Reranker 对 bounded candidate set 的相关性排序。
- `Evidence`：最终进入证据集的知识单元，含 immutable Source。
- `EvidenceSet`：Conversation 唯一依赖的检索输出。

## 4. 不变量
- 所有候选必须来自同一个 Active Snapshot。
- Retrieval 不允许返回无法定位 source commit/path/lines 的 Evidence。
- lexical/vector 原始 score 不直接线性相加；V0 用 rank fusion 解决量纲不同问题。
- Reranker 失败时可以退回 RRF 排序，但不能因此伪造 rerank score。
- 没有足够证据时必须能输出 low-confidence/no-evidence，而不是强行凑满 Top-K。

## 5. 主流程
`Standalone Query → Lexical Recall + Vector Recall → Deduplicate → RRF → Rerank → Evidence Selection → EvidenceSet`。

## 6. 与其他领域关系
Retrieval 只读取 Knowledge 发布的 Active Snapshot。它不管理聊天历史；Conversation 负责把多轮指代改写为 Standalone Query。Retrieval 把完整 trace 数据发布给 Evaluation，但在线回答不依赖 Evaluation 写入成功。

## 7. 验收
同一问题能解释“哪些候选来自 lexical、哪些来自 vector、RRF 后排第几、Reranker 后为何进入最终证据”；对中文自然语言、英文术语、函数名、路径、CLI 和错误串均有专门 benchmark；无证据问题能够稳定拒答/降级。
